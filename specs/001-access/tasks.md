# Задачи среза 001

Формат строки: `- [ ] T-NNN [P] [исполнитель] описание — путь или тест — (FR-NNN)`.
`[P]` — можно делать параллельно с соседними задачами. Исполнитель — haiku /
sonnet / opus / человек (по разделу «Разделение работы между моделями» в
docs/sdd-process.md). Задачи собраны из PLAN-001 и SPEC-001 (18 сценариев,
FR-001…055, NFR-001…011); ни одной задачи вне плана здесь нет, а чего плану
не хватило — раздел «Ответы на вопросы к плану».

Как читать и исполнять:
- **Порядок.** Этапы идут подряд; внутри этапа задача без `[P]` ждёт
  предыдущую, а задачи с `[P]` независимы от соседей. Нумерация: Этап 1 —
  T-001…, Этап 2 — T-100…, Этап 3 — T-200…, Этап 4 — T-300….
- **Тест-на-требование.** В Этапе 2 у каждого теста в скобках стоит FR или
  NFR, который он закрывает; запись `файл::имя_теста` — это и есть связь
  T-NNN → FR → тест. Приёмка сценариев 1–18 — сценарии Playwright
  `backend/tests/e2e/…`.
- **Красный прежде зелёного.** Задачи Этапа 3 не начинаются, пока не сделана
  T-152 (красный прогон): тесты сначала падают, и это записано. Тест не
  ослабляют, чтобы он прошёл: правят код, а правка теста — только с причиной в
  отчёте.
- **Размер.** Одна задача — не больше полудня работы одного исполнителя.
- **Секреты — только `***`** (в коде, документах, отчётах, выводе команд):
  каждому исполнителю это правило ставится в задание. Пароль в тестах не
  литерал, а `secrets.token_urlsafe()` из общей фикстуры.
- **Черновик Haiku на подпись напрямую не идёт:** его работу (T-002, T-004)
  проверяет Sonnet (T-003) и затем Opus на воротах (Этап 4).
- Ссылки на разделы плана — в названии задачи («раздел …») или в `(план: …)`.
