# T-9305 — наблюдения на стенде (задачи), план до запуска

Основание: TASKS-009 T-9305 (наблюдения с разрешения владельца, после копии); разрешение владельца
2026-11-24 («закрыть прежние открытые задачи до старта среза 011»). Наполнение стенда берётся из прогона
T-9304 (100 учёток, 1 000 задач, 930 комментариев, 191 напоминание) — поэтому наблюдения идут после T-9304
и до сброса стенда в T-7304.

Порядок: последовательно, без параллельных прогонов; тексты наблюдений служебные и вымышленные; ПДн нет;
секреты не выводятся.

## 1. Отказ слоя уведомлений (FR-691, NFR-714)

Цель: недоступный слой каналов не теряет задачу и уведомление; действие не падает; в журнале — предупреждение
без названия и описания задачи.

1. Временный модуль настроек `/tmp/t9305/publish_down_settings.py`: `from config.settings import *`, затем
   `CHANNEL_LAYERS["publish"]["CONFIG"]["hosts"] = [{"address": "redis://valkey:6399/0", "socket_timeout": 2,
   "socket_connect_timeout": 2}]` (порт 6399 никто не слушает).
2. Временный контейнер образа `crm-portal:local` в сети `crm_default` с `DJANGO_SETTINGS_MODULE=publish_down_settings`,
   `PYTHONPATH=/tmp/t9305`; скрипт на вход `manage.py shell`: взять двух действующих сотрудников стенда, создать
   задачу службой `tasks.services.create` (обычный путь), замерить время, вывести номер задачи, число уведомлений
   и `created`, перечитать строку задачи из базы.
3. Проверки: код возврата 0, задача в базе, уведомление назначенному создано (`notify.Notification`), время
   действия не больше 3 с, в журнале контейнера — `Рассылка в группы уведомлений не удалась: <ТипОшибки>`,
   названия задачи в журнале нет.
4. Убрать временный контейнер и каталог настроек.

## 2. Повтор задания напоминаний (NFR-715, FR-691)

1. На наполнении T-9304: `tasks_reminders(now)` с `now = сейчас + 12 ч` — первый запуск отправляет созревшие
   напоминания; число `pending` до и после, число новых уведомлений по видам `tasks.*`, число записей
   `tasks.reminder_failed`.
2. Повторный запуск с тем же `now`: новых уведомлений нет, `tasks.reminder_failed` не растёт, ошибок нет.
3. Артефакт — вывод обоих запусков и сводные числа до/после.

## 3. Ночная уборка на наполнении (FR-696, NFR-715)

1. Подготовка: у 50 задач из наполнения выставить `deleted_at` старше границы хранения (календарное вычитание
   лет от сегодня) прямым `UPDATE` в контейнере `standtools`; записать числа задач, комментариев и файлов.
2. `tasks_retention(now)`: замер времени, числа `tasks/comments/files/unbound`, запись `tasks.retention_purged`
   в журнале — одна.
3. Повторный запуск: числа нули по удалению, лишних записей журнала нет, ошибок нет.
4. Проверка непривязанных файлов старше 24 часов — если на стенде их нет, записывается «0».

## Артефакты

`crm-work/slice009/stage4/T-9305/<запуск>/` — журналы наблюдений, времена, числа, вывод `docker ps`; отчёт —
`docs/reviews/TASKS-009.md`, раздел «Наблюдения на стенде (T-9305)».

## Ограничения

- Стенд после наблюдений не восстанавливается до наполнения: следующий шаг — T-7304, он начинает со сброса.
- Службы `scheduler` и `worker-mail` не останавливаются; штатные `worker-notify` не трогаются (слой ломается
  только внутри временного контейнера).
