# T-8305 — наблюдения на стенде (план, до запуска)

Основание: TASKS-008 T-8305 (наблюдения с разрешения владельца, после копии), разрешение владельца 2026-11-19
(«T-8305 — после T-8302»). Стенд занят приёмкой T-8302; наблюдения выполняются после её завершения.

## 1. Слой `publish` (адрес закрыт)

Цель (NFR): отправка сообщения не ждёт слой, сообщение цело, предупреждение в журнале, страницы работают.

Порядок:
1. Копия стенда штатная (как в update-stand) — не требуется: изменения только временные контейнеры.
2. Временный модуль настроек `/tmp/t8305/publish_down_settings.py`: `from config.settings import *`, затем
   `CHANNEL_LAYERS["publish"]["CONFIG"]["hosts"] = [{"address": "redis://valkey:6399/0", "socket_timeout": 2, "socket_connect_timeout": 2}]`
   (порт 6399 никто не слушает).
3. Остановить штатные `worker-notify` (две копии), поднять временный контейнер того же образа и сети с
   `DJANGO_SETTINGS_MODULE=publish_down_settings`, `PYTHONPATH=/tmp/t8305`, команда
   `rq worker -c config.rq_settings --with-scheduler notify`; журнал — `docker logs`.
4. В контейнере `web` (боевые настройки, стенд) клиентом Django: `force_login` тестовым сотрудником, замер
   POST `/messenger/chats/<id>/messages/` (обычный POST → 302), проверка строки сообщения в базе, GET `/messenger/` 200.
   Порог — 3 с на отправку.
5. Ожидаемое предупреждение в журнале временного воркера — `Рассылка мессенджера не доставлена (ConnectionError…)`,
   без текста переписки.
6. Убрать временный контейнер, вернуть `worker-notify`.

## 2. Пауза Valkey 60 с

1. `docker pause crm-valkey-1` на 60 с.
2. Замеры (клиент Django в `web`): главная `/`, страница списка `/messenger/`, отправка сообщения (порогов нет —
   фиксируются времена и коды; ожидается 500 или отказ, данных не теряем).
3. `docker unpause crm-valkey-1`; проверки: `/` 200, `/messenger/` 200/302, отправка после паузы проходит;
   вкладки (браузер) сами возвращаются в `open` в пределах ~60 с.

## 3. Пересоздание службы `web`

1. `docker compose -p crm -f deploy/docker-compose.yml --profile dev up -d --no-deps --force-recreate web`.
2. Браузер (Playwright, стенд): открытая беседа и колокольчик — коды закрытия сокетов (разрешены 1012 и 1006),
   затем самостоятельное возвращение в `data-ws="open"` (до ~60 с); после — отправка сообщения проходит.

## Артефакты

`crm-work/slice008/stage4/T-8305/<запуск>/` — журналы наблюдений, времена, коды закрытия, вывод `docker ps`.
Секретов и текстов переписки в отчёте нет; сообщения наблюдений — «наблюдение T-8305 N».

## Ограничения

- Наблюдения меняют состояние стенда (временные контейнеры, пауза Valkey, пересоздание `web`); выполняются
  последовательно, после T-8302 и без параллельных прогонов.
- Службы `scheduler`/`worker-mail` не останавливаются; тексты сообщений — только служебные, вымышленные.
