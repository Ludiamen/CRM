## Итоговая сверка (F1, F2)
- **F1** (0 / 2 / 5): каждая из 70 находок получила решение; `opus_apply.py`,
  пересобранный на снимке до правок, даёт тот же текст, что после правок, — в дифф не

  формы; журнал nginx пишет `$uri` без параметров (риск переписан); порциями должны

  HTMX не подставил бы (в `htmx-glue.js` нет обработки 4xx) — отказ стал ответом 200 с
  сообщением; IP у заявки с формы пишется по SPEC-001 FR-044.

Opus проверил по файлам сам: `rq/cron.py:118` и `rq/utils.py` (UTC), `log_format` в
`deploy/nginx.conf` (`$uri`), отсутствие обработки 4xx в `htmx-glue.js`, FR-044 в SPEC-001.

## Что владельцу знать при подписи
Технические решения плана принимал Opus; они утверждаются подписью. Ниже — те, что
сужают, дополняют или толкуют спеку, и новые службы установки.

**Поведение для заявителей и исполнителей**
1. Над закрытой заявкой доступны только «Открыть заново» и внутренний комментарий;
   назначение, передача, поля, статус и ответ — после открытия (FR-246, FR-249).
2. Ответ, вложения которого ещё проверялись, когда заявку закрыли, не уходит («ответ
   не отправлен: заявка закрыта»); после открытия — «Отправить заново» (FR-244).
3. Архив с паролем, который распознал только ClamAV (вложенный, 7z со сжатым
   заголовком), отмечается в карточке после проверки и в уже ушедшее подтверждение не
   попадает (FR-285).
4. Исполняемые файлы — по содержимому и по последнему расширению имени: `exe`, `com`,
   `scr`, `pif`, `bat`, `cmd`, `msi`, `msp`, `vbs`, `vbe`, `js`, `jse`, `wsf`, `wsh`, `ps1`,
   `hta`, `cpl`, `jar`, `lnk`, `reg`, `sh`; офисные файлы с макросами (`docm`, `xlsm`) не
   считаются исполняемыми. Правило одно для писем, формы и ответов исполнителя.
5. Тема заявки не правится; адреса из «Кому» (кроме ящика) участниками не становятся
   (FR-217 называет только копию).
6. Название портала в письмах — в имени отправителя, тексты писем — ровно по спеке
   (FR-257, FR-258).
7. Отсчёт автозакрытия идёт с постановки ответа в очередь писем, а не с доставки.
8. Поиск — слова от 2 знаков, до 8 слов; в поиск попадает не больше 300 тыс. знаков
   текста заявки (FR-278 пределов не называет).
9. Пресет списка по умолчанию — «Мои очереди» (у не участника очередей — «Мои»);
   групповое действие — до 100 заявок; ручное «Снять ответственного» без письма.
10. ФИО у заявки исполнителя необязательно (FR-219); пока список доменов пуст, заявку не
    заведёт и исполнитель («закрыто по умолчанию»).

**Письма и ящик**
11. Кроме адреса ящика, отклоняются и письма с адреса отправки портала `SMTP_FROM`
    (шаг 1 FR-214); письмо без адреса в `From` — как чужой домен.
12. Пересоздание ящика: разбираются письма, пришедшие не раньше чем за 10 минут до
    последнего удачного опроса прежнего ящика, кроме уже известных по `Message-ID`.
13. Письма с ошибкой разбора тоже стираются через 30 дней как «не связанные с заявкой»
    (FR-221); у них хранится только шаг и класс ошибки, без текста.
14. Вложенное письмо — одно вложение `.eml`.

**Справочники, загрузка, очереди**
15. Снятие отметки очереди без открытых заявок проходит, её категории переводятся в
    очередь по умолчанию (сценарий 9.3); узел-очередь без заявок не удаляется, пока не
    снята отметка (дополнение к FR-107).
16. Пустое ФИО записи заявителя заполняется из письма или формы; пустые ячейки таблицы
    заявителей прежние значения не стирают.
17. Чтение CSV и XLSX переносится из `org` в ядро (общее для двух загрузок); тесты
    загрузки сотрудников не меняются и проверяют перенос.

**Установка и эксплуатация**
18. Новые службы: `worker` в двух копиях (проверка файлов), `worker-mail` (письма и
    периодические задания, очередь `maintenance`), `worker-inbox` (ящик), `backup`
    (ночная копия базы и файлов в 01:30, хранение 14 дней); на стенде ещё `dovecot`.
19. `rq cron` считает время по UTC: ночные задания срезов 001–002 («03:10») фактически
    идут в 06:10 по Москве — здесь не меняются; задания среза 003 поставлены на
    02:10–02:50 по Москве.
20. `IMAP_SECURITY=none` допустим только на стенде; страница настроек предупреждает.
21. Номера заявок могут идти с пропусками (откат транзакции); после восстановления из
    копии счётчик сдвигается на 1000 (`servicedesk_after_restore`).
22. Если Valkey недоступен, порог формы не действует (заявка важнее порога).
23. Фраза о нерабочем времени без даты, если рабочего дня нет 400 дней вперёд.
