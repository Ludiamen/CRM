### Новая F-12 — P1: `SET_NULL` целевой стадии разрушает ключ идемпотентности

**Точные ссылки:** PLAN-015:154–159,258–259,520–522;
SPEC-015:166–184,478–481.

Исправление F-02 обнуляет теперь **обе** исторические FK, но уникальный ключ и поиск повтора
по-прежнему используют nullable FK `to_stage`. Снимок названия сохраняет читаемость истории,
но не сохраняет идентификатор целевой стадии.

Контрпример в разрешённом объёме:

1. Запись переходит A → B с `base_version=v`, затем B → C с новой версией.
2. Пустая B удаляется по FR-854; у первой строки `StageMove.to_stage` становится NULL.
3. Доставляется повтор первого запроса `(record, v, id_B)`. Сотрудник по-прежнему читает запись на C.
4. Проверка чтения проходит, но поиск сохранённого ключа больше не находит строку:
   в базе NULL вместо `id_B`. Дальше получится конфликт версии либо отказ из-за удалённой цели,
   а не сохранённый результат повтора по FR-872.

**Нужно:** отделить неизменяемый идентификатор цели в ключе повтора от необязательной исторической FK
(например, числовой снимок `to_stage_key` без каскадного обнуления, используемый в ограничении и поиске).
Повтор искать по исходному ID до загрузки/валидации существования целевой стадии, но по-прежнему после
актуальной проверки чтения записи. Добавить тест A → B → C, удаление пустой B, повтор `(v, id_B)`:
тот же сохранённый результат, без нового перехода/истории/журнала.
Это сохранение подписанного контракта, не расширение среза.

## Находки

### F-01 — P1: `StageMove.from_stage` не допускает переход из «Без стадии»

**План:** `specs/015-process-constructor/plan.md:140–143,227–236`.
`from_stage` задан FK `PROTECT` без `null` (в отличие от явно nullable `actor` и `Record.stage`).
Для записи с `stage=NULL` строку перехода сохранить нельзя.

**Основа:** `specs/015-process-constructor/spec.md:71–74,178–181,383–384`: запись без стадии
разрешена, держатель правки списка может перевести её на видимую стадию; переход должен сохранить историю.

**Исправление:** явно разрешить пустую исходную стадию, описать её показ в истории/журнале и тест
перехода `NULL → открытая/закрытая` с повторной доставкой и проверкой прав списка.

### F-02 — P1: исторические FK `PROTECT` запрещают разрешённое удаление пустой стадии

**План:** `specs/015-process-constructor/plan.md:142–143,212–214`.
После A → B на A может не остаться записей, но `StageMove.from_stage=А` защищает A от удаления.
Это дополнительный запрет, отсутствующий в подписанном правиле.

**Основа:** `specs/015-process-constructor/spec.md:102–104,140–141,372–376,426–427`.
База должна защищать стадию с текущими записями через `Record.stage`; стадию без записей разрешено удалить,
история переходов при этом сохраняется.

**Исправление:** разделить текущую ссылку `Record.stage` и историческое представление стадий
(например, сохранять идентификатор/название перехода, а необязательную историческую FK обнулять).
Не менять подписанное право удаления. Тест: A → B, удалить пустую A, история остаётся читаемой.

### F-03 — P1: перечень интеграции видимости не закрывает реальные независимые выборки
