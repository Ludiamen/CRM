# Отчёт проверки REF-SRC

Вердикт: **годен к подписи**, после исправления одиннадцати строк реестра
(десять — путь или опорная фраза не были дословными/точными; одна дала
предупреждение только из-за ограничений моего скрипта, не из-за ошибки в
реестре, и правки не потребовала). Полный текст реестра, который проверяет
этот отчёт, приведён к состоянию, где путь существует и опорная фраза
подтверждается дословно для всех 92 источников из дистрибутива и для всех
семи выборочно проверенных страниц документации.

## Метод

- Реестр насчитывает 115 строк: `SRC-001…011` и `SRC-101…112` — страницы
  документации (23 шт.), `SRC-201…275`, `SRC-301…327`, `SRC-350…360` —
  дистрибутив пробной коробки (92 шт., дыры в нумерации — это разные партии
  находок, не пропуски). Дубликатов номеров нет, колонка «Про что» заполнена
  во всех 115 строках (`awk` по таблицам, отдельная проверка).
- **Дистрибутив** (92 строки) проверен скриптом
  (`scratchpad/verify_sources.py`, приложен ниже отдельным разделом): для
  каждой строки скрипт (1) разбирает колонку «Где» (учитывает `;`- и
  `,`-разделённые группы путей, общий каталог `lang/ru/`, аннотации
  `$MESS[...]`), (2) проверяет, что файл(ы) существуют под
  `/home/gpgr/Документы/bitrix24_encode/bitrix/modules/`, (3) ищет опорную
  фразу в содержимом файла после нормализации: `\"` → `"`, снятие настоящих
  HTML-тегов (но не голого `<?` PHP — это отдельно чинил, первая версия
  скрипта случайно вырезала текст между `<?` и первым `>` во всём файле),
  схлопывание пробелов/переносов строк, `ё`→`е` (частая орфографическая
  вариация, не ошибка). Фраза с `«…»`/`;` разбивается на части, и каждая
  часть ищется как самостоятельная подстрока — так various схемы регистра
  «нашёл дословно, но по кускам» не считаются ложным совпадением.
- **Страницы документации** (23 строки) скриптом не проверяются (сеть).
  Проверено выборочно 7 штук через WebFetch, включая обе страницы, у которых
  в самом реестре уже есть замечания о ненадёжности (`SRC-003`, `SRC-104`) —
  как и просил владелец задания.
