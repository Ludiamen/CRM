### Находки для Opus
Блокирующих нет.

Важные.
1. Последствия, второй пункт: «`servicedesk` и ядро поставляют поиск заявок, сотрудников и подразделений». Подразделения принадлежат приложению `org` (`org/directory.py`, `Unit`, `Membership`; TGT-ARCH — строка `org`), а сотрудники — каталогу ядра (`core.services.accounts.directory_staff`) вместе с расширением `org`. Нужно: «`servicedesk`, ядро и `org`» (или указать, кто поставляет какую группу). Заодно в «Последствиях» нет правки документов, которые ADR прямо оговаривает в «Решении»: TGT-ARCH (строка `knowledge` — «обсуждение» уходит в ядро как общий комментарий; «видимость статьи — по правам рубрики» заменена на «опубликованные видны всем, черновики — автору и управляющим»; в строке `core` — комментарии) и REF-CAP (CAP-15: «заявки, задачи, сотрудники» против четырёх групп с подразделениями). Сейчас уточняется только UX-02. Источник: `architecture.md`, строки 62, 84–86; `capabilities.md`, CAP-15. Важность: важная.
2. Решение 2, «восстанавливают из корзины … — с правом „Управление базой знаний“». В ответе владельца (вопрос 2) право управления названо для «удалять и вести рубрики»; кто возвращает статью из корзины, сказано только в вопросе 3 («можно вернуть») без указания права. Это вывод Opus и должен быть помечен «(вывод Opus)». Так же без пометки в решении 11: «виден автору и управляющим» — в тексте владельца «тем, кто управляет базой» (смысл тот же, замечание формальное). Источник: `owner-answers-2026-10-18.md`, вопросы 2, 3, 11. Важность: важная (происхождение решений).

Мелкие.
3. «Последствия» не называют, что для вложений статей ядро получает новое назначение файла через уже существующую точку `file_purposes` (`core/tasks.py`, `core/extensions.py`) и что вставка картинок в текст требует выдачи файла сотруднику с проверкой права на статью (X-Accel, `architecture.md`, строки 133–136). Кроме того, ADR не упоминает новые зависимости (разметка Markdown и санитайзер HTML — в `requirements.txt` их нет; CSP без `unsafe-inline`, значит и кнопки панели — только vendor-скрипт). По процессу это раздел «Новые компоненты и лицензии» плана; достаточно одной строки «зависимости — решение плана».
4. Сводка владельцу: ПДн в статьях. ADR не говорит, что обезличивание заявок через срок хранения (`servicedesk/services/retention.py`, `retention_years`) не затрагивает уже опубликованные статьи и связь «статья — заявка»; инвариант «пдн-152фз» требует «срока хранения». Решение 12 это смягчает, но пробел стоит назвать (хотя бы «статьи бессрочны, ответственность автора — решение владельца по вопросу 12»).
5. Контекст, «поиском „в этом вики-проекте“ (SRC-215)»: в `sources.md` SRC-215 — «Результаты поиска; Создать страницу %LINK% в этом вики-проекте»; цитата «в этом вики-проекте» относится к созданию страницы, а не к области поиска. Предложение: «поиском по базе знаний (SRC-215)» без кавычек.
6. Шапка: ADR-0009 назван в «Контексте» (срез 009), но не указан в `зависит_от`; в ADR-0011 перечислены все упомянутые решения. Предложение: добавить ADR-0009 (по желанию — REF-UX уже есть).

### Что не проверялось
Файлы дистрибутива эталона (SRC-210…215 и прочие) не открывались: опора на `sources.md`. Стенд, тесты и docker не запускались; `.env` не читался. Реализуемость (рендер Markdown без `unsafe-inline`, поиск ≤ 1 с на двух приложениях, предупреждение при одновременной правке) — вне задания и за планом.
