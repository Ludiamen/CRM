## Назначение модуля

В дистрибутиве модуль описан так: «Модуль позволяющий организовать на сайте систему обращений посетителей к группе, ответственной за консультирование и техподдержку клиентов вашей компании». Заявитель обращения — посетитель сайта/клиент («клиент техподдержки»), а не сотрудник организации; обрабатывают обращения «сотрудники техподдержки» и «администратор техподдержки». Модуль также даёт управление очередями обращений, назначение ответственных, отслеживание SLA и времени решения, анализ качества обслуживания (SRC-107).

## Сущности

| Сущность | Что это | Атрибуты | Связь с другими |
|---|---|---|---|
| Обращение в техподдержку | Запрос посетителя сайта/клиента на помощь в решении проблемы | номер, название, описание, категория, критичность, статус, дата создания, дата решения, автор, исполнитель | может быть связано с объектом проблемы |
| Категория обращения | Классификация типов проблем | название, описание, назначенная группа поддержки | используется для распределения обращений; у категории можно задать ответственного по умолчанию (SRC-262) |
| Критичность | Приоритет решения обращения | уровень, привязка к SLA | определяет приоритет в очереди |
| SLA (Service Level Agreement, «Уровень техподдержки») | Соглашение об уровне обслуживания | название, приоритет, время реакции на сообщение клиента, расписание работы, ответственный по умолчанию, привязанные категории и критичности | применяется к категориям или уровням критичности (SRC-263) |
| Группа поддержки | Команда сотрудников техподдержки, обслуживающих обращения | название, члены-сотрудники, доступ к сообщениям группы | обрабатывает обращения из назначенных категорий |
| Сообщение | Запись в цепи обсуждения обращения | текст, автор, время, вложения, видимость (внутреннее/внешнее) | часть обращения |
| Расписание работы | График работы по обращениям с конкретным SLA | часы работы по дням, режим «24 часа»/«не работает» | учитывается при расчёте срока реакции SLA (SRC-110, SRC-263) |
| Справочник техподдержки | Набор классификаторов обращения — не база статей, а списки значений: категории, критичности, уровни сложности, статусы, источники, оценки ответов, частые ответы | тип справочника, значение, ответственный, сортировка | используется при заведении и обработке обращения; частые ответы — заготовленные тексты ответа (SRC-265) |
| Купон/Ваучер | Код, дающий обращению SLA по умолчанию для купонов (например, ускоренную обработку) | формат кода, привязанный SLA | может быть выдан клиенту (SRC-265) |

## Экраны и элементы интерфейса

- **Список уровней поддержки и форма уровня** (административная часть): название, приоритет, время реакции на
  сообщение клиента, расписание работы, привязанные категории и критичности, ответственный по умолчанию (SRC-263,
  SRC-262).
- **Расписание работы** задаётся для конкретного SLA и учитывается при расчёте срока реакции (SRC-110, SRC-263).
- **Очередь обращений**: список с фильтрацией и сортировкой; просрочка видна в очереди, ответственный получает
  напоминание по почте до истечения срока (SRC-107, SRC-263).
- **Форма обращения**: при выборе категории или SLA можно установить ответственного по умолчанию; автозакрытие при
  отсутствии ответа клиента через заданное число дней (SRC-262).
- **Справочник «Частые ответы»**: административный список заготовленных текстов; оператор выбирает готовый ответ
  вместо повторного набора (SRC-265).
- **Оценка ответов**: заявитель ставит оценку ответу оператора; в административном списке обращений есть сортировка
  по оценке ответов (SRC-262).
- **Административный отчёт по обращениям** (график `ticket_report_graph`): существует, набор метрик в описях не
  раскрыт (SRC-107).

## Сценарии

- **Заведение уровня поддержки.** Администратор создаёт уровень: название, приоритет, время реакции, расписание,
  привязанные категории/критичности, ответственный по умолчанию (SRC-263, SRC-262).
- **Создание обращения и установка срока.** Обращение получает категорию (и через неё — уровень SLA); по уровню
  считается срок реакции от сообщения клиента с учётом расписания работы (SRC-107, SRC-110, SRC-263).
- **Контроль срока.** Просрочка видна в очереди; ответственному уходит напоминание по почте до истечения срока
  (SRC-107, SRC-263).
- **Ответ частым ответом.** Оператор выбирает «частый ответ» и вставляет его в ответ на обращение (SRC-265).
- **Оценка ответа.** Заявитель (клиент) ставит оценку ответу; оценка доступна в списке и отчётах (SRC-262, SRC-107).
- **Отчёт по обращениям.** Административный отчёт показывает показатели по обращениям; сортировка списка по оценке
  ответов доступна и в самом списке (SRC-107, SRC-262).

## Права и роли

- Сотрудник техподдержки обрабатывает обращения, администратор техподдержки ведёт справочники, уровни и настройки
  (SRC-107).
- Участнику группы поддержки можно отдельно разрешить читать тикеты группы и/или получать уведомления группы
  независимо от назначения ответственным (SRC-327).

  администратор техподдержки)?]

## Настройки администратора

- Уровни поддержки (SLA): название, приоритет, время реакции, расписание, привязки, ответственный по умолчанию
  (SRC-263, SRC-262).
- Справочник частых ответов и уровень поддержки по умолчанию для купонов (SRC-265).
- Автозакрытие обращения при отсутствии ответа клиента через заданное число дней (SRC-262).

## Уведомления

- Ответственному — напоминание по почте до истечения срока реакции (SRC-107, SRC-263).
- Участнику группы — уведомления группы, если право включено (SRC-327).

## Связи с другими модулями

- **CRM** — связь с контактами и компаниями CRM не подтверждена источником, см. «Что неясно»
- **Открытые линии** — обращения можно направлять в систему техподдержки (см. модуль «Открытые линии»)
- **Задачи** — преобразование обращения в задачу для выполнения
- **Диск** — прикрепление документов к обращениям
- **Бизнес-процессы** — автоматизация обработки обращений
