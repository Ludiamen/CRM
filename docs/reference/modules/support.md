## Назначение модуля

В дистрибутиве модуль описан так: «Модуль позволяющий организовать на сайте систему обращений посетителей к группе, ответственной за консультирование и техподдержку клиентов вашей компании». Заявитель обращения — посетитель сайта/клиент («клиент техподдержки»), а не сотрудник организации; обрабатывают обращения «сотрудники техподдержки» и «администратор техподдержки». Модуль также даёт управление очередями обращений, назначение ответственных, отслеживание SLA и времени решения, анализ качества обслуживания.

## Сущности

| Сущность | Что это | Атрибуты | Связь с другими |
|---|---|---|---|
| Обращение в техподдержку | Запрос посетителя сайта/клиента на помощь в решении проблемы | номер, название, описание, категория, критичность, статус, дата создания, дата решения, автор, исполнитель | может быть связано с объектом проблемы |
| Категория обращения | Классификация типов проблем | название, описание, назначенная группа поддержки | используется для распределения обращений |
| Критичность | Приоритет решения обращения | уровень, привязка к SLA | определяет приоритет в очереди |
| SLA (Service Level Agreement, «Уровень техподдержки») | Соглашение об уровне обслуживания | название, приоритет, время реакции, расписание, ответственный по умолчанию, привязанные категории и критичности | применяется к категориям или уровням критичности |
| Группа поддержки | Команда сотрудников техподдержки, обслуживающих обращения | название, члены-сотрудники, доступ к сообщениям группы | обрабатывает обращения из назначенных категорий |
| Сообщение | Запись в цепи обсуждения обращения | текст, автор, время, вложения, видимость (внутреннее/внешнее) | часть обращения |
| Расписание работы | График работы по обращениям с конкретным SLA | часы работы по дням, режим «24 часа»/«не работает» | учитывается при расчёте срока реакции SLA |
| Справочник техподдержки | Набор классификаторов обращения — не база статей, а списки значений: категории, критичности, уровни сложности, статусы, источники, оценки ответов, частые ответы | тип справочника, значение, ответственный, сортировка | используется при заведении и обработке обращения |
| Купон/Ваучер | Код, дающий обращению SLA по умолчанию для купонов (например, ускоренную обработку) | формат кода, привязанный SLA | может быть выдан клиенту |

## Связи с другими модулями

- **CRM** — связь с контактами и компаниями CRM не подтверждена источником, см. «Что неясно»
- **Открытые линии** — обращения можно направлять в систему техподдержки (см. модуль «Открытые линии»)
- **Задачи** — преобразование обращения в задачу для выполнения
- **Диск** — прикрепление документов к обращениям
- **Бизнес-процессы** — автоматизация обработки обращений

## Возможности — кандидаты в карту эталона

| Возможность | Что делает | Используют | Источник |
|---|---|---|---|
| Создание обращений через форму | Посетитель сайта/клиент отправляет обращение в техподдержку через веб-форму | посетители сайта, клиенты | SRC-107, SRC-261 |
| Получение обращений по почте | Автоматическое создание обращений на основе входящих писем (источник обращения помечается как «почта») | система, операторы | SRC-107, SRC-265 |
| Категоризация и распределение | Обращению назначается категория из справочника, категория связана с группой поддержки и SLA | система, диспетчер | SRC-107, SRC-262 |
| Управление очередями обращений | Просмотр, фильтрация и сортировка обращений по различным критериям | операторы, супервизоры | SRC-107 |
| Назначение ответственного | Назначение сотрудника для решения конкретного обращения; у SLA есть ответственный по умолчанию | диспетчер, супервизор | SRC-107, SRC-263 |
| Отслеживание SLA | Контроль соблюдения времени реакции по уровню техподдержки (SLA), напоминание по почте до истечения срока | система, супервизоры, аналитики | SRC-107, SRC-263 |
| История обращений | Сохранение полной истории переписки и действий по обращению | все пользователи, аналитики | SRC-107 |
| Закрытие обращений | Завершение обращения с указанием решения; предусмотрено автозакрытие при отсутствии ответа клиента | операторы, супервизоры | SRC-107, SRC-262 |
| Оценка ответов | Клиент/автор обращения может поставить оценку ответам оператора | клиент, аналитики | SRC-262 |
| Создание уровней поддержки | Администратор создаёт уровни техподдержки (SLA) с приоритетом, временем реакции, расписанием и привязанными категориями | администраторы | SRC-107, SRC-263 |
| Расписание работы группы поддержки | Расписание работы задаётся для конкретного SLA и учитывается при расчёте срока реакции | администраторы | SRC-110, SRC-263 |
| Справочник техподдержки | Ведение классификаторов: категории, критичности, уровни сложности, статусы, источники, оценки ответов | операторы, супервизоры, администраторы | SRC-262 |
| Частые ответы (шаблоны ответов) | Оператор выбирает заготовленный «частый ответ» вместо повторного набора типового текста | операторы | SRC-265 |
| Отчёты по эффективности | Административный отчёт (график) по обращениям; сортировка списка обращений по оценке ответов | супервизоры, аналитики, руководители | SRC-107 |
| Наблюдатель в группе поддержки | Участнику группы отдельно от назначения ответственным можно разрешить читать тикеты группы и/или получать её уведомления — то есть следить за очередью, не будучи исполнителем | операторы, супервизоры | SRC-327 |
