# ADR-0002: Разработка по SDD — каркас ГИС, эталон вместо legacy

## Контекст
Битрикс КП — это десятки модулей с неявными правилами (права на задачи,
жизненный цикл заявки, кто видит запись в ленте). Если строить портал «по
памяти о Битриксе», правила теряются, а границы MVP расплываются. Каркас SDD
уже отработан в проекте ГИС: инварианты с «почему» и «вместо» из агента Дня 20,
ворота с подписью и отпечатком (`tools/sdd.py`, 60 тестов), шаблоны
документов, разделение работы между моделями.

## Решение
Решения владельца от 2026-09-29:
- **Каркас ГИС целиком**: раскладка GitHub Spec Kit (constitution → spec →
  plan → tasks), конституция в JSON в формате инвариантов Дня 20, статус и
  подпись с отпечатком во frontmatter, проверка `tools/sdd.py`.
- **Слой legacy заменён слоем «эталон»**: вместо ссылок `путь:строка` на
  старый код — источники `SRC-NN` (документация 1С-Битрикс и снимки
  демо-установки), зарегистрированные в `docs/reference/sources.md`.
- **Глубина эталона — карта и приёмы интерфейса**: карта возможностей
  Битрикс КП по всем модулям с решением по каждой (MVP / позже / не нужно) и
  документ приёмов интерфейса; подробная опись — только модулей с
  возможностями MVP и «позже».
- **Источники эталона** — публичная документация плюс демо-установка коробки.
- **Исполнитель** — Claude Code с разделением работы между Haiku, Sonnet и
  Opus (docs/sdd-process.md); утверждает только человек.

## Альтернативы
- Чистый GitHub Spec Kit — отклонён: нет машинной проверки конституции,
  подписей и отпечатков.
- Облегчённый вариант без подписей и ворот — отклонён: утверждение ничем не
  защищено от правки задним числом.
- Полная спецификация всех модулей Битрикса (как as-is в ГИС) — отклонён:
  дорого, и большая часть уйдёт в «не нужно».
- Только свои требования без разбора эталона — отклонён: владелец хочет
  интерфейс и функции «как в Битриксе», и без описи это требование
  непроверяемо.

## Последствия
- `tools/sdd.py` переделан: вид `as-is` заменён видами `эталон`, `требования`,
  `архитектура`; проверка ссылок на legacy — проверкой ссылок на код и
  реестра источников; трассировка считает покрытие спеками возможностей MVP.
- Фильтр `redact` из ГИС не нужен (legacy нет); остался pre-commit
  `tools/check_secrets.py` против секретов в новом коде.
- Демо-установка требует скачивания дистрибутива 1С-Битрикс и действует
  30 дней пробного периода: снимки экранов надо снять в этот срок.
