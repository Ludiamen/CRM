# ADR-0003: Поиск, файлы, универсальные списки и приём почты

## Контекст
В MVP 34 возможности (REF-CAP). Четыре из них требуют решения, которое
конституция и ADR-0001 не задают. Нужен сквозной поиск по заявкам, статьям,
сотрудникам, ленте и спискам (CAP-15). Вложения приходят из интернета — с
открытой формы без входа и из писем (CAP-23, CAP-22, CAP-62). Учёт
оборудования и лицензий должен настраиваться без кода (CAP-105, инвариант
«настройка-без-кода»). Письма заявителей надо забирать с собственного
почтового сервера общества по IMAP (REQ-CTX). Объёмы малы: до 100
сотрудников, до 1000 заявителей, до 100 заявок в день.

## Решение
Поиск, файлы и списки — выбор владельца от 2026-09-30:
- **Поиск — полнотекстовый поиск PostgreSQL** с русской морфологией
  (конфигурация `russian`). У каждой сущности, по которой ищут, есть
  столбец `tsvector` с GIN-индексом. Модуль отдаёт результаты через свой
  `services.search()`, где права доступа проверяются прямо в запросе.
  Отдельного поискового сервиса нет.
- **Файлы — том на ВМ плюс антивирус ClamAV.** Вложение сначала
  сохраняется со статусом «проверяется», затем задание RQ передаёт его
  `clamd` в отдельном контейнере. Заражённый файл уходит в карантин и
  недоступен. Файл отдаётся только после проверки права, через внутренний
  адрес nginx (`X-Accel-Redirect`); прямой ссылки на файл нет.
  Администратор копирует том вместе с базой.
- **Учёт оборудования и лицензий — универсальные списки.** Администратор
  сам создаёт список и его поля (текст, число, дата, справочник, сотрудник,
  подразделение, файл). Значения хранятся в JSONB с GIN-индексом, выгрузка
  в Excel есть. Списки «Оборудование» и «Лицензии» создаются миграцией
  данных при установке, дальше их правят без кода.
- **Приём почты — опрос IMAP раз в минуту** заданием планировщика RQ.
  Это решение Opus, владелец его отдельно не выбирал: он утверждает его
  подписью под этим ADR или возвращает на доработку.
  Письмо сначала сохраняется целиком и только потом разбирается (инвариант
  «интеграции-через-адаптеры»). Ответ заявителя привязывается к заявке по
  номеру в теме и по заголовкам `In-Reply-To` и `References`.

## Альтернативы
- Meilisearch — отклонён: ещё один сервис, синхронизация индекса и
  отдельная фильтрация по правам; поиск с опечатками при этих объёмах не
  окупает затрат.
- Том без антивируса — отклонён: файлы приходят от неаутентифицированных
  отправителей из интернета.
- MinIO — отклонён: сложнее резервное копирование, а объектное хранилище
  понадобится не раньше диска (CAP-64, «позже»).
- Готовые реестры оборудования и лицензий с фиксированными полями и
  гибрид «реестр + свои поля» — отклонены: новое поле добавлялось бы
  релизом, либо в системе было бы два механизма вместо одного.
- IMAP IDLE (постоянное соединение) — отклонён: сложнее переподключение, а
  задержка до минуты для заявок допустима. Передача писем почтовым сервером
  прямо в портал — отклонена: требует настройки чужого сервера.

## Последствия
- В составе Docker Compose появляется контейнер `clamav` (около 1 ГБ
  памяти, базы сигнатур обновляются сами).
- Отчёты по спискам строятся по JSONB. Если спискам понадобятся сложные
  отчёты, возможно, придётся перейти на готовые модели.
- Письмо заявителя превращается в заявку не мгновенно, а в пределах
  нефункционального требования (TGT-NFR).
