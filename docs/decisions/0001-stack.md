# ADR-0001: Стек — Django + HTMX + PostgreSQL, как в Газоwiki

## Контекст
Портал ИТ-отдела повторяет по поведению и интерфейсу «1С-Битрикс:
Корпоративный портал» (коробка): сервис-деск, задачи и проекты, оргструктура,
лента, чат, календарь, диск, база знаний. Учётные записи — около 100
сотрудников ИТ; заявители работают без учётной записи через почту и открытую
форму (REQ-CTX). Портал доступен из интернета. Разрабатывает и сопровождает
один человек вместе с Claude Code, параллельно с проектами Газоwiki
(Django + HTMX) и ГИС (Django + GeoDjango).

## Решение
Выбор владельца от 2026-09-29 — стек Газоwiki:
- **Сервер** — Django 5.x; фоновые задачи — django-rq на Redis; живые
  обновления (чат, лента, счётчики) — Django Channels на ASGI-сервере с
  channels-redis; API на DRF — только там, где он нужен интеграции.
- **Интерфейс** — шаблоны Django + HTMX, Alpine.js для локального состояния,
  Bootstrap 5 со своей темой, SortableJS для перетаскивания (канбан).
- **База** — PostgreSQL 17, в тестах тоже.
- **Вход** — свои учётные записи (не домен) с обязательной двухфакторной
  авторизацией: django-otp (TOTP + резервные коды), django-axes от перебора.
- **Развёртывание** — Docker Compose на ВМ Debian за обратным прокси,
  который публикует штатный администратор.
- **Имена** (вывод по аналогии с Газоwiki и ГИС, доведён до владельца —
  возражений не было) — в коде английские, интерфейс и документация русские,
  имена файлов латиницей.

## Альтернативы
- Django API + SPA (Vue 3 / React) — отклонён владельцем: интерфейс ближе к
  Битриксу, но два стека, дублирование проверок прав на клиенте и заметно
  больше кода для одного сопровождающего.
- Решить стек после карты возможностей — отклонён: состав модулей Битрикса
  известен заранее, и ни один из них не требует SPA; откладывание только
  задерживало бы конституцию.
- Вход доменной учётной записью (LDAP / Kerberos) — отклонён владельцем в
  пользу своих учётных записей.
- Коробочный Битрикс КП — не рассматривается: цель проекта — своя система.

## Последствия
- Три проекта на одном стеке: общие приёмы (двухфакторная авторизация, RQ,
  тема Bootstrap) переносятся между ними.
- Живые обновления требуют ASGI-сервера и Redis уже в MVP, если в MVP попадут
  чат или лента.
- Жёсткие инварианты «стек-бэкенд», «стек-интерфейс», «бд» проверяются
  `tools/sdd.py` по каталогам backend/, frontend/, deploy/.
- Сервер — виртуальная машина на Debian в ресурсах общества; в интернет его
  публикует штатный администратор, резервные копии лежат на локальном и
  сетевом хранилище внутри периметра (REQ-CTX). Контейнеры и пути томов
  должны это позволять: база и файлы — в томах, которые копируются снаружи.
