# ADR-0006: Блокировка входа при общем адресе филиала

Уточняет NFR-12 в TGT-NFR. Остальные требования TGT-NFR не меняются.

## Контекст
NFR-12 требует после 5 неудачных попыток входа блокировать на 15 минут и
учётную запись, и адрес IP. Филиалы общества могут выходить в интернет
через один общий адрес (NAT; это уже отмечено в NFR-15 для открытой формы).
Тогда один сотрудник, ошибившийся паролем 5 раз, на 15 минут закрывает вход
всему филиалу. Вопрос всплыл при подготовке спеки среза 001 (SPEC-001).

## Решение
Выбор владельца от 2026-10-01:
- **Учётная запись блокируется всегда:** 5 неудачных попыток входа (как в
  NFR-12) закрывают вход в эту запись на 15 минут. Это решение владельца.
  Предложения, не выбранные владельцем и утверждаемые подписью: слово
  «подряд» (успешный вход обнуляет счётчик); подсчёт неверного кода второго
  фактора как неудачной попытки; письмо сотруднику о блокировке.
- **Адрес IP блокируется только при переборе разных учётных записей с
  него**, а не из-за ошибок одного человека. Порог — настройка, по умолчанию
  20 неудачных попыток по разным учётным записям с одного адреса за 15
  минут, блокировка адреса — на 15 минут. Пороговые числа — предложение
  Opus, владелец выбрал сам принцип; числа утверждаются подписью.
- Предложение, не выбранное владельцем: администратор может снять
  блокировку записи или адреса раньше срока. Журналирование каждой
  блокировки и разблокировки — следствие инварианта «аудит-изменений»
  (NFR-16), не отдельный выбор.

Владелец выбрал принцип «запись — всегда, адрес — при переборе по разным
записям». Детали — подсчёт неверного кода второго фактора как неудачной
попытки, ручное снятие блокировки, письмо о блокировке, пороговые числа —
предложения (черновик SPEC-001 и Opus), они утверждаются подписью.

## Альтернативы
- Оставить NFR-12 как есть и принять риск блокировки филиала — не выбрано
  владельцем. Довод против (Opus): 15 минут без входа для целого филиала
  из-за одной опечатки — чаще, чем атака.
- Не блокировать адрес вовсе — не предлагалось: тогда перебор многих
  учётных записей с одного адреса ничем не сдерживается.

## Последствия
- NFR-12 в TGT-NFR читается вместе с этим ADR. Когда TGT-NFR будет
  перевыпускаться, уточнение вносится в его текст, а ADR-0006 помечается
  «заменён».
- Остаточный риск, принятый вместе с решением: перебор по 4 попытки на
  каждую из многих учётных записей с одного адреса идёт ниже порога
  блокировки записи, и адрес блокируется только по общему порогу (по
  умолчанию 20 за 15 минут, то есть после 4–5 записей). Медленный перебор
  растянутым по времени остаётся заметен только в журнале событий.
- Тесты и проход в браузере среза 001 проверяют оба порога: пять
  ошибок одной записи и серию ошибок по разным записям с одного адреса.
