# ADR-0010: Умные напоминания о сроках задач; push в браузере; основа — в срезе 004, правила — в срезе 009

Дополняет ADR-0004 (состав среза 004 «Уведомления и приглашения») и ADR-0009
(срез 009 «Задачи»). Уточняет строку CAP-14 карты возможностей (REF-CAP) и
добавляет строку CAP-115. Число возможностей MVP не меняется (38); объём
CAP-14 внутри MVP растёт.

## Контекст
2026-10-08 владелец написал (дословно —
crm-work/notify/owner-request-2026-10-08.md): нужна система умных напоминаний
для исполнителей и руководителей о контрольных сроках по выполняемым и
назначаемым задачам; напоминания — на электронную почту и push-уведомлениями
в браузере; напоминания должны настраиваться у каждого пользователя, как и
другие уведомления.

Что уже решено. Уведомления на портале и почтой с выбором каналов
пользователем — CAP-14, MVP, срез 004 (ADR-0004; модуль `notify` в TGT-ARCH).
Push в браузере в CAP-14 и TGT-ARCH не назван. Контрольные сроки есть только у
задач — срез 009, первый после MVP (ADR-0009). У заявок сервис-деска сроков
нет: контроль сроков SLA (CAP-31) отложен.

Как в эталоне. В задаче можно поставить напоминание «за N дней» до срока
письмом или мгновенным сообщением (SRC-366); сама задача пишет «Задача почти
просрочена» за сутки до срока и «Задача просрочена» после него, а автоматика
стадий умеет отслеживать «Скоро просрочена» и «Просрочена» (SRC-367). В
настройках уведомлений пользователь выбирает каналы, среди них «Push
уведомления» (SRC-276, SRC-368); для push эталону нужен отдельный push-сервер —
свой или облачный сервер производителя (SRC-369).

Opus предложил варианты и задал владельцу четыре вопроса; ответы — ниже.
Вопросы и варианты дословно — в том же файле требования. Ниже в «Решении»
текст выбранных вариантов пересказан; уточнения Opus сверх него помечены
«(вывод Opus)».

## Решение
Ответы владельца от 2026-10-08:

1. **Напоминания — о сроках задач** (ответ 1). Заявки сервис-деска напоминания
   о сроках получат позже, вместе со сроками SLA (CAP-31), на той же основе.
2. **Push в браузере — оба вида, Web Push — настройкой** (ответ 2):
   - **во вкладке портала** — системное уведомление браузера, пока открыта
     вкладка портала; приходит по уже запланированному каналу WebSocket
     (Channels) (вывод Opus), внешних сервисов не нужно; работает всегда;
   - **Web Push** — уведомление приходит и при закрытой вкладке через
     push-сервисы производителей браузеров (Google, Mozilla и др.). Включает
     администратор портала; каждый пользователь сам разрешает его в своём
     браузере. По инварианту «пдн-152фз» в Web Push уходят только событие и
     ссылка, без ФИО и текста задачи. Нужны ключи VAPID в окружении и выход в
     интернет с сервера портала.
3. **Основа — в срезе 004, правила — в срезе 009** (ответ 3). Срез 004
   «Уведомления» (MVP) строит основу: каналы (портал, почта и push), личные
   настройки «какое событие — каким каналом», отложенную отправку и тихие
   часы по рабочему календарю. Основа — общая для всех модулей (вывод Opus);
   push — в двух видах по ответу 2; сводки — по ответу 4 (вывод Opus).
   Срез 009 «Задачи» добавляет сами напоминания о сроках: сроки появляются
   только там.
4. **Виды напоминаний — все четыре предложенных** (ответ 4):
   - **заранее и при просрочке** — исполнителю (и соисполнителям — вывод
     Opus): за N рабочих часов или дней до срока по рабочему календарю, в
     момент срока и при просрочке — как «почти просрочена» и «просрочена» в
     эталоне;
   - **руководителю — просрочка и сводка** — постановщик и руководитель
     получают уведомление, когда задача подчинённого просрочена; раз в рабочий
     день — сводку просроченных и «горящих» задач подчинённых;
   - **«Напомнить» вручную и «отложить»** — в задаче можно поставить себе
     напоминание на дату или «за N дней до срока», как в эталоне; пришедшее
     напоминание можно отложить;
   - **тихие часы и без лишнего** — в нерабочее время напоминания не шлются,
     а накапливаются и приходят с началом рабочего дня; одно событие не
     повторяется по всем каналам сразу; после завершения задачи её напоминания
     снимаются.

   Каждый пользователь включает и выключает виды напоминаний у себя и выбирает
   для них каналы (слова вопроса 4) — в тех же личных настройках, что и
   остальные уведомления (слова требования владельца).

## Альтернативы
Варианты, которых владелец не выбрал. Доводы против — Opus.
- Напоминания сразу и о задачах, и о заявках. Не выбрано: у заявок нет
  контрольных сроков; пришлось бы поднять CAP-31 (сроки SLA по критичности) из
  «позже» — заметно больше работы, чем просил владелец.
- Push только во вкладке портала. Не выбрано: при закрытом портале напоминание
  пришло бы только почтой.
- Только Web Push. Не выбрано: без настройки администратора нельзя отказаться
  от передачи событий на серверы производителей браузеров; без вкладочного
  канала push не работает там, где выход в интернет закрыт.
- Всё в срезе 009 (срез 004 — только портал и почта). Не выбрано: личные
  настройки уведомлений и каналы пришлось бы перестраивать второй раз.
- Отдельный срез 010 «Умные напоминания» после задач. Не выбрано: задачи
  вышли бы без напоминаний о сроках, хотя сроки — их суть.

## Последствия
- **Срез 004 «Уведомления»** (спека 004 определяет состав; предложения Opus):
  - каталог видов уведомлений: каждый модуль регистрирует свои виды (код,
    название по-русски, каналы по умолчанию, можно ли отключить) через точку
    расширения ядра — по образцу точек срезов 002–003;
  - каналы: на портале (список уведомлений и счётчик, толчок по WebSocket),
    почта, push во вкладке (Notifications API по WebSocket, пока вкладка
    открыта), Web Push (служебный скрипт браузера, подписки по устройствам,
    протокол Web Push с шифрованием содержимого и ключами VAPID); Telegram и
    MAX (CAP-39) встают в тот же каталог каналов;
  - личные настройки: таблица «вид уведомления × канал» у каждого пользователя
    (как настройки уведомлений эталона, SRC-276), значения по умолчанию задаёт
    администратор; тихие часы — по рабочему календарю среза 002 (CAP-79) или
    по личным часам пользователя;
  - отложенная отправка: уведомление с моментом «не раньше» и сводки
    (накопленное за нерабочее время — одним уведомлением или письмом в начале
    рабочего дня); задания RQ по расписанию;
  - без дублей: одно событие — одна запись уведомления, каналы — её доставки;
    если вкладка портала открыта, уведомление показывается во вкладке, а Web
    Push не уходит; правило для почты (сразу или если не прочитано за N
    минут) — решение спеки 004;
  - Web Push — адаптер `integrations/webpush` через очередь с повтором
    (инвариант «интеграции-через-адаптеры»); ключи VAPID — только в окружении
    (`.env`, инвариант «секреты-вне-кода»); подписка, на которую push-сервис
    отвечает «не существует», удаляется; содержимое — только событие и ссылка
    («пдн-152фз»: push-сервисы — чужие серверы, как Telegram и MAX);
  - выход в интернет с сервера портала к push-сервисам производителей
    браузеров — требование к размещению; без него работают портал, почта и push
    во вкладке. Какой push-сервис у Яндекс.Браузера и поддерживает ли он Web
    Push в нужном объёме — проверить при подготовке плана среза 004;
  - новые сторонние библиотеки (клиент Web Push) — с лицензией в плане среза
    004 (таблица «Новые компоненты и лицензии»), только из разрешённого стека
    (ADR-0001).
- **Срез 009 «Задачи»** (спека 009 определяет состав; предложения Opus):
  - правила напоминаний — виды уведомлений модуля `tasks` в каталоге среза 004:
    «скоро срок» (за N рабочих часов или дней, по умолчанию — за один рабочий
    день, как «почти просрочена» эталона), «срок наступил», «просрочена»
    (исполнителю и соисполнителям), «просрочена задача подчинённого»
    (постановщику и руководителю), «сводка по подчинённым» (раз в рабочий день),
    «вы просили напомнить» (ручное напоминание);
  - пересчёт при смене срока, снятие при завершении и удалении задачи;
    «отложить» — на выбор пользователя (например, на час или до начала
    следующего рабочего дня);
  - руководитель и подчинённые — по структуре среза 002, как видимость задач
    подчинённых в ADR-0009.
- **Заявки** — напоминания о сроках встанут на ту же основу вместе с CAP-31
  (сроки SLA), когда до него дойдёт.
- **REF-CAP (версия 5):** строка CAP-14 дополнена push в браузере (во вкладке и
  Web Push настройкой), отложенной отправкой, тихими часами и сводками; новая
  строка CAP-115 «Умные напоминания о сроках задач» — решение «позже», срез 009
  (как CAP-44). Число возможностей — 115; MVP — 38, позже — 53, не нужно — 24.
- **REF-SRC (версия 8):** добавлены SRC-366…369.
- **TGT-ARCH и ADR-0004** — каналы push, адаптер `integrations/webpush`,
  каталог видов уведомлений и отложенная отправка войдут в их текст при
  перевыпуске; до тех пор действует этот ADR.
- **Конституция не меняется** (вывод Opus): Web Push подпадает под действующие
  инварианты «пдн-152фз», «секреты-вне-кода» и «интеграции-через-адаптеры»,
  хотя «пдн-152фз» называет внешними каналами только Telegram и MAX, а
  «интеграции-через-адаптеры» Web Push не перечисляет. Для Web Push правило
  «только событие и ссылка» владелец принял в ответе 2. При следующей версии
  конституции дописать Web Push в перечни обоих инвариантов.
- **Объём среза 004** после этого ADR заметно больше: каталог видов
  уведомлений, четыре канала, Web Push, отложенная отправка, сводки. Делить ли
  срез на части — решает спека 004.
