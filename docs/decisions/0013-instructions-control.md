# ADR-0013: Контроль поручений — отдельный модуль, срез 010 после «Задач»; сроки отчётов и лестница напоминаний

Дополняет ADR-0004 и ADR-0009 (порядок срезов): после среза 009 «Задачи» идёт срез 010 «Поручения». Дополняет
ADR-0010 (напоминания о сроках): для поручений — лестница напоминаний по длине срока и напоминания о сроках отчётов.
Добавляет в карту возможностей (REF-CAP) строку CAP-116. Состав MVP не меняется.

## Контекст
2026-10-21 владелец поручил проверить, есть ли в требованиях постановка задач и контроль поручений с уведомлениями о
приближении срока отчёта, в том числе для поручений со сроком исполнения полгода–год (дословно —
crm-work/slice005/owner-answers-2026-10-21-stage4.md, п. 2). Проверка Opus: постановка задач и напоминания о сроках
задач решены (ADR-0009, ADR-0010; CAP-44, CAP-46, CAP-73, CAP-115; срез 009). Контроля поручений нет: нет контролёра,
сроков отчёта, отличных от срока исполнения, отчёта об исполнении с принятием, переноса срока по согласованию и
напоминаний, рассчитанных на длинные сроки (ADR-0010 даёт только «за N рабочих часов или дней»). В эталоне
поручения входят в модуль задач («управления задачами и поручениями», SRC-001); отчётных дат и принятия отчёта
контролёром в описях эталона не найдено — есть наблюдатели (SRC-250) и напоминание «за N дней» до срока (SRC-366).

Владелец ответил на три круга вопросов, варианты предложил Opus (дословно — crm-work/poruch/owner-answers-2026-10-21.md).

## Решение
Ответы владельца от 2026-10-21:

1. **Поручение — отдельный модуль «Поручения»** (круг 1, ответ 1), а не признак задачи: как в СЭД, у поручения своё
   основание (приказ, протокол совещания), резолюция, свой реестр и свои правила контроля.
2. **Срез 010 — сразу после «Задач»** (круг 2, ответ 1). Порядок: 001–008 (MVP, ADR-0004), 009 «Задачи» (ADR-0009),
   010 «Поручения». Срез опирается на уведомления среза 004 и рабочий календарь среза 002.
3. **Кто ставит и кто контролирует** (круг 1, ответ 2). Поручения ставит руководитель (и заместитель) своим
   подчинённым — по структуре, как задачи в ADR-0009. Контролёр по умолчанию — постановщик; постановщик может
   назначить контролёром другого сотрудника (например, помощника или секретаря).
4. **Основание** (круг 2, ответ 2). У поручения — вид основания из справочника (например, приказ, протокол
   совещания, письмо, устное указание), номер и дата документа и файл документа (проверка ClamAV, как у вложений).
   Один документ-основание — несколько поручений.
5. **Исполнители** (круг 3, ответ 1). Один ответственный исполнитель — пишет отчёт и отвечает за срок; соисполнители
   видят поручение, получают напоминания и добавляют свои части отчёта.
6. **Сроки** (круг 1, ответ 3). Срок исполнения и отчётные даты: периодичность (еженедельно, ежемесячно,
   ежеквартально) или список дат. Для поручений на полгода–год это контроль хода работы, а не только итога.
7. **Отчёт и снятие с контроля** (круг 2, ответ 3). К каждой отчётной дате и к сроку исполнения ответственный
   исполнитель пишет отчёт (текст и файлы); контролёр принимает его или возвращает на доработку с комментарием.
   С контроля поручение снимает только контролёр.
8. **Перенос срока** (круг 2, ответ 4). Исполнитель просит перенос с причиной; постановщик (или контролёр)
   соглашается или отказывает. Все переносы видны в истории поручения и в журнале; исходный срок сохраняется для
   отчётности.
9. **Напоминания — лестница по длине срока** (круг 1, ответ 4). По умолчанию набор напоминаний зависит от длины
   срока: для длинных поручений — за 30, 14, 7, 3 и 1 рабочий день до срока исполнения, в момент срока и при
   просрочке; о каждой отчётной дате — за 3 и 1 рабочий день. Постановщик может поправить лестницу у поручения,
   администратор — умолчания. Вывод Opus, не ответ владельца: дни считаются по рабочему календарю (на него срез
   опирается — круг 2, ответ 1), тихие часы и каналы — из среза 004, как в ADR-0010.
10. **Кому что приходит** (круг 3, ответ 2). Исполнителям — лестница по сроку исполнения и отчётам. Контролёру и
    постановщику — просрочка отчёта и срока, пришедший отчёт, запрос переноса и еженедельная сводка «на контроле:
    сроки на ближайший месяц и просроченные». Каналы каждый выбирает в своих настройках уведомлений (CAP-14).
11. **Реестр и дисциплина** (круг 3, ответ 3). Реестр поручений с фильтрами (мои, на моём контроле, подчинённых,
    просроченные, по основанию); отчёт по исполнительской дисциплине за период (исполнено в срок, с переносом,
    просрочено) по сотрудникам и отделам; выгрузка в Excel.
12. **Связь с задачами** (круг 3, ответ 4). Исполнитель может разложить поручение на задачи среза 009 (себе и своим
    подчинённым); задачи связаны с поручением и видны в нём, но на контроль поручения не влияют — отчёт пишет
    исполнитель.

## Альтернативы
Варианты, которые предлагал Opus и которых владелец не выбрал:
- Чем поручение должно быть: задача среза 009 с признаком «на контроле» (рекомендация Opus) — не выбрано, владелец
  выбрал отдельный модуль; только задачи и напоминания ADR-0009/0010 без контроля.
- Когда делать: в MVP сразу после среза 005 (сдвинет первый выпуск); вместе с «Задачами» в одном срезе 009.
- Кто ставит и контролирует: контролёр всегда постановщик, передать контроль нельзя; любой сотрудник любому
  (расходится с правилом ADR-0009 для задач).
- Сроки: срок исполнения и один срок отчёта («исполнить до …, доложить до …»); только срок исполнения.
- Напоминания: только «за N дней» из ADR-0010; одна фиксированная лестница для всех.
- Основание: только текст поручения; основание строками без файлов.
- Отчёт: отчёт без принятия (исполнитель сам отмечает исполнение); только отметка «исполнено» без текста.
- Перенос срока: переносит только постановщик без запросов; срок не переносится (нужно новое поручение).
- Исполнители: каждому — своё поручение; только один исполнитель.
- Напоминания и сводки: всем участникам одинаково; только исполнителю.
- Просмотр: только реестр с фильтрами; реестр и канбан по срокам без отчёта по дисциплине.
- Связь с задачами: поручения и задачи независимы; поручение само уходит на принятие, когда все связанные задачи
  готовы.

## Последствия
- Порядок срезов: 001–008 (MVP), 009 «Задачи», 010 «Поручения». При перевыпуске ADR-0004 это войдёт в его текст.
- REF-CAP (версия 6): новая строка CAP-116 «Контроль поручений» — решение «позже», срез 010.
- Состав среза 010 определяет его спека. Предложения Opus для спеки: правило «кто кому ставит поручения» выразить
  правами по образцу ADR-0009 (инвариант «настройка-без-кода»); справочник видов основания ведёт администратор;
  лестницу напоминаний по умолчанию задать порогами длины срока (например, до месяца — за 3 и 1 день; до полугода —
  добавить за 14 и 7; дольше — добавить за 30), точные пороги — в спеке; отчёт по дисциплине считает «исполнено в
  срок» по исходному сроку и отдельно — по сроку с переносами; во внешние каналы (Telegram, MAX, Web Push) уходят
  только событие и ссылка, без текста поручения и основания (инвариант «пдн-152фз», как в ADR-0010).
- Напоминания о сроках задач (ADR-0010, срез 009) и о сроках поручений (срез 010) строятся на одной основе
  уведомлений среза 004; общий механизм расписания напоминаний делает срез 009, срез 010 его переиспользует
  (вывод Opus).
