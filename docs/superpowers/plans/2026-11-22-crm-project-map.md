# Интерактивная карта CRM — Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Показывать, что реализовано, что проходит приёмку и что предстоит, без ручного дублирования чек-листов.

**Architecture:** Отдельный локальный инструмент читает рабочую копию репозитория и отдаёт карту только на loopback. При открытии и обновлении карта считает прогресс заново; история изменений берётся из Git и отделяется от текущих незакоммиченных отметок.

**Tech Stack:** Python 3 (стандартная библиотека), HTML/CSS/JavaScript без внешних зависимостей.

**Spec:** Запрос владельца об интерактивной карте; источники и правила интерпретации закреплены ниже. Это инструмент разработчика, не экран портала.

## Общие ограничения

- Не менять `backend/`, `deploy/`, подписанные документы и штатный процесс приёмки.
- Не читать `.env`, журналы стенда и `crm-work/` автоматически, не открывать рабочую копию по сети. HTTP отдаёт только страницу и подготовленные данные карты, не произвольные файлы.
- Все статусы объяснимы по ссылкам на источники. Процент — доля отмеченных задач, не готовность релиза или оценка объёма труда.

## Модель данных

- `specs/NNN-*/spec.md`, `plan.md`, `tasks.md`: название, статус документов, задачи с идентификаторами `T-*`. Нумерованные чек-листы внутри задач и примеры кода не считать.
- `docs/reviews/TASKS-NNN.md`: ссылка на подтверждение приёмки. Если факт приёмки не извлекается надёжно, показывать «не подтверждено картой», даже при 100% отметок. Для исключений ранних срезов допускается небольшая таблица ссылок на явно зафиксированные решения, но не ручные проценты.
- `docs/reference/capabilities.md`: «позже», «не нужно» и MVP брать из колонки **«Решение»**, а не из предложения. Возможность из «позже», уже включённую в срез, не показывать как нетронутую. Наличие ссылки CAP в спеке означает запланированное покрытие, не приёмку.
- `git`: короткий SHA и дата последнего изменения источников карты; история по коммитам показывает появившиеся, снятые и добавленные отметки по идентификаторам. Незакоммиченные изменения — отдельный слой; обновление не выполняет `fetch`.
